# 一、基本概念

# 静态链接

将库的代码直接编译到最终的可执行文件中，生成一个完整的、独立的程序。

# 动态链接

库的代码在运行时才加载到内存中，可执行文件只包含对库的引用。

# 二、两种链接方式的对比

特性 静态链接 动态链接
文件大小 较大，包含所有库代码 较小，只有引用
内存占用 每个程序独立占用 多个程序可共享
部署难度 简单，单个文件 需要确保系统有对应库
更新库 需要重新编译 替换库文件即可
启动速度 较快 需要加载动态库，稍慢
运行时性能 可能略好（无间接调用） 有轻微开销

# 静态链接文件

# 主要类型： .lib 文件（静态库）

这是 Windows 下的标准静态库文件，直接包含目标代码。

特点：

  • 在编译链接时被完整复制到可执行文件中

  • 可执行文件不依赖外部库文件

  • 文件通常较大

  • 使用 add_library(foo STATIC ...) 生成

# 静态库的 .lib （STATIC）

运行时不需要，但分发时可能需要（取决于你的分发形式）

编译完成后：

  • ✅ 代码已完整嵌入 myapp.exe

  • ❌ 运行 myapp.exe 不需要 mylib.lib

  • ⚠️ 但如果你要重新编译或让其他人链接你的库，就需要保留这个 .lib

# 动态链接文件

动态链接在 Windows 下涉及两个文件：

# 1. .dll 文件（Dynamic Link Library）

  • 运行时必需的真正动态库

  • 包含实际的函数代码和数据

  • 程序运行时加载到内存

# 2. .lib 文件（导入库 / Import Library）

  • 编译链接时使用的导入库

  • 与静态库同名但内容完全不同

  • 仅包含 DLL 中导出符号的存根（stub）信息

  • 告诉链接器如何找到 DLL 中的函数

这是 Windows 特有的设计：同名 .lib 文件根据生成方式不同，内容完全不同。

# 动态库的 .lib （导入库 / SHARED）

编译完成后不需要 .lib ，但必须要有 .dll

编译完成后：

  • ❌ 不需要 mydll.lib - 导入库只用于编译链接阶段

  • ✅ 必须要有 mydll.dll - 运行时动态加载这个

# 文件对比总结

文件类型 扩展名 何时使用 内容 是否独立
静态库 .lib 编译时 完整目标代码 是
导入库 .lib 编译时 DLL 符号存根 否，需.dll 配合
动态库 .dll 运行时 实际代码和数据 是（运行时）
场景 需要.lib 吗？ 需要.dll 吗？
--- --- ---
自己编译 exe（静态链接） 编译时需要 永远不需要
自己编译 exe（动态链接） 编译时需要 运行时需要
分发 exe（静态链接） 不需要 不需要
分发 exe（动态链接） 不需要 需要
提供 SDK 给别人开发用 需要（两种.lib 都要） 如果动态链接还需要.dll
重新编译项目 需要.lib 动态链接还需要.dll
